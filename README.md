# 歌唱比赛小程序 (Song Contest Mini Program)

一个微信小程序，用于歌唱比赛的**微信登录**、**选手报名**与**授权评委打分**，并自动计算最终成绩、排名和冠军。

## 功能

- **微信登录 (Login)**：使用微信头像 + 昵称登录（`chooseAvatar` + `type="nickname"`，符合当前微信规范）。登录信息保存在本地。
- **报名 (Signup)**：登录后**自动填入微信昵称**作为姓名（可修改）；录入演唱曲目、语言（国语/粤语/英语/日语/韩语/其他）、原唱、联系方式、备注。
- **选手列表 (Contestants)**：查看所有报名选手、打分进度，进入打分。
- **评委打分 (Judge)**：**仅授权评委可进入**。5 位评委分别打分，每位评委按 4 个维度评分（满分 100）：
  - 音准/唱功 (40)
  - 情感表达 (30)
  - 台风表现 (20)
  - 综合印象 (10)
- **成绩排行 (Results)**：自动计算最终成绩、排名，并高亮显示冠军 👑。
- **我的 (Profile)**：查看登录状态、是否为授权评委、授权名单，退出登录。

## 权限控制（评委打分）

进入打分页前会校验两步：

1. **必须已登录**（否则提示登录）。
2. **登录昵称必须在授权评委名单中**（否则提示无权限）。

每位评委绑定一个固定座位（seat，0 起的评委序号），在 `app.js` → `globalData.authorizedJudges` 中配置，按昵称匹配（忽略大小写与首尾空格）。默认示例：

```js
authorizedJudges: [
  { name: '评委一', seat: 0 },
  { name: '评委二', seat: 1 },
  { name: '评委三', seat: 2 },
  { name: '评委四', seat: 3 },
  { name: '评委五', seat: 4 }
]
```

> 说明：纯前端 / 无后端模式下，身份由本地保存的微信昵称判断。若需防篡改的强身份校验，应配合 `wx.login` + 后端（如微信云开发）用 openid 作为授权键。

## 归属与编辑规则

- **报名删除：只有报名本人可删**。报名需先登录，报名记录会记下 `owner`（登录昵称）。选手列表中，只有 `owner` 与当前登录用户一致时才显示「删除报名」按钮，且删除时再次校验归属。
- **评委只能改自己的分**：登录评委被锁定在自己的座位，打分页只显示/可编辑**本座位**，其他评委的分数只读、不可更改。
- **提交后不可修改**：评委提交自己的打分后即锁定，输入框禁用、不再显示提交按钮，无法再编辑或覆盖。
- 全局 **成绩页 → 清空所有数据** 仍可一次性清除**全部**选手与打分（管理员重置用途）。

## 计分规则

每位选手由 5 位评委打分，每位满分 100。当**全部 5 位评委**打完后：

1. 去掉一个**最高分**和一个**最低分**；
2. 取剩余 3 位评委的**平均分**作为最终成绩。

不足 5 位评委时，暂取已打分评委的平均分作为预览，待打满后按上述规则计算。

## 数据存储（微信云开发 / 多设备同步）

选手与打分数据存在**微信云开发数据库**，所有人用自己的手机看到的是**同一份实时数据**。

- 本地仅保存 `currentUser`（登录身份 `{ name, avatar, loginAt }`，每台设备各自登录）。
- 云数据库集合：
  - `contestants`：每条一个报名，含 `owner`（昵称）与 `_ownerOpenid`（真实身份，用于删除鉴权）。
  - `scores`：**每个评委每位选手一条独立文档** `{ contestantId, seat, dims, total, by, byOpenid, at }`。独立文档意味着多位评委**同时打分也不会相互覆盖**。
- 所有写操作走云函数 `contest`（以管理员权限运行），用调用者真实 `openid` 执行鉴权：
  - 删除报名：仅 `_ownerOpenid === 调用者` 才允许。
  - 提交打分：若该 `(选手, 座位)` 已存在则拒绝（**提交后锁定，不可改**）。
  - 清空数据：需管理员 PIN（默认 `1234`，在 `cloudfunctions/contest/index.js` 的 `ADMIN_PIN` 修改）。

### 开通云开发（必做一次）

1. 用**微信开发者工具**打开本项目（AppID 已设为 `wx3a197be20381ee07`）。
2. 工具栏点击 **云开发 (CloudBase)** → **开通**，创建一个环境（免费基础版即可），记下 **环境 ID（Env ID）**，形如 `song-contest-1xxxxxxx`。
3. 把环境 ID 填到 `app.js` → `globalData.cloudEnv`（替换 `REPLACE_WITH_YOUR_CLOUD_ENV_ID`）。
4. 在资源管理器右键 `cloudfunctions/contest` 文件夹 → **上传并部署：云端安装依赖**。
5. 重新编译。首次报名 / 打分时，云数据库会自动创建 `contestants`、`scores` 集合。

> 费用：对 20 人以内、5 位评委的比赛，用量远低于云开发免费额度，实际 ¥0。免费额度为配额而非永久承诺；超出当日配额会**暂停到次日**，不会突然扣费。

### 测试

1. 在「我的」登录，昵称填 `评委一`（名单中任意一个）→ 可进入打分；填其他昵称会被拦截。
2. 报名后，用另一台设备（或开发者工具的真机预览）登录 `评委二`，能看到同一份选手与进度，验证**多设备同步**。

## 目录结构

```
app.js / app.json / app.wxss      全局配置、云环境、授权名单与样式
project.config.json               项目配置（AppID + cloudfunctionRoot）
sitemap.json                      索引配置
cloudfunctions/
  contest/                        云函数：报名/打分/删除/清空（带鉴权）
utils/
  db.js                           调用云函数的客户端封装
  score.js                        计分/排名纯函数（输入云数据）
  auth.js                         登录会话 + 评委授权/座位校验
pages/
  index/                          首页（概览 + 登录入口）
  login/                          微信登录（头像 + 昵称）
  signup/                         选手报名（自动填昵称，写云端）
  contestants/                    选手列表（读云端，下拉刷新）
  judge/                          评委打分（权限校验，读写云端）
  results/                        成绩排行 + 冠军 + 清空数据（PIN）
  profile/                        我的（登录状态 / 授权名单 / 关于）
```

## 自定义

- 修改云环境 ID：`app.js` → `globalData.cloudEnv`。
- 修改管理员清空 PIN：`cloudfunctions/contest/index.js` → `ADMIN_PIN`（改后需重新部署云函数）。
- 修改授权评委名单：`app.js` → `globalData.authorizedJudges`。
- 修改评委人数：`app.js` → `globalData.judgeCount`。
- 修改评分维度/权重：`app.js` → `globalData.dimensions`（各维度 `max` 之和应为 100）。
